# PRD: Система контроля выполнения задач сотрудниками сети АЗС

**Версия документа:** 1.0
**Дата:** 08.08.2026
**Автор:** составлено на основе рабочей переписки с владельцем сети
**Статус:** описывает функциональность реализованного прототипа (`azs_control.html`)

---

## 1. Назначение и контекст

Продукт — веб-инструмент для операционного контроля за выполнением задач сотрудниками сети автозаправочных станций (АЗС). Он даёт руководителю сети единую картину: какие задачи поставлены, кто за них отвечает, соблюдаются ли сроки, и позволяет напрямую связаться с ответственным сотрудником через WhatsApp, если задача просрочена или требует внимания.

### 1.1 Проблема

В сети из нескольких АЗС ежедневно выполняется большой объём однотипных операционных, товароведческих и управленческих задач (приём смены, инкассация, проверка ассортимента, отчётность по реализации, работа с поставщиками и т. д.). Без единой системы контроля руководство не имеет оперативной видимости того, где задачи выполняются вовремя, а где систематически срываются сроки, и кто из сотрудников за это отвечает.

### 1.2 Масштаб сети (на момент составления PRD)

| Параметр | Значение |
|---|---|
| Количество АЗС | 7 |
| Менеджеры | 2 (каждый курирует группу АЗС) |
| Начальник торгового отдела | 1 (курирует товароведов по всей сети) |
| Товароведы | 3 (каждый закреплён за 2–3 АЗС) |
| Сотрудники смен | по 2 на станцию (дневная и ночная смена) — 14 человек |

### 1.3 Целевые пользователи

- **Владелец / руководитель сети** — просматривает сводный дашборд, отслеживает просрочки, ставит задачи любому сотруднику.
- **Менеджер АЗС** — отвечает за состояние закреплённых станций и отчётность по реализации топлива и сопутствующих товаров.
- **Начальник торгового отдела** — контролирует заявки на пополнение ассортимента и работу с поставщиками по всей сети.
- **Товаровед** — отвечает за наличие ассортимента, ценники, сроки годности и отчёт по реализации товаров на закреплённых станциях.
- **Сотрудник смены (оператор/кассир)** — исполнитель чек-листа состояния АЗС в рамках своей смены.

## 2. Организационная структура и зоны ответственности

Инструмент моделирует реальную иерархию сети:

```
Начальник торгового отдела
 └── курирует всех товароведов и работу с поставщиками по сети (7 АЗС)

Менеджер 1 ─── АЗС №1, №2, №3, №4
Менеджер 2 ─── АЗС №5, №6, №7

Товаровед 1 ─── АЗС №1, №2, №3
Товаровед 2 ─── АЗС №4, №5
Товаровед 3 ─── АЗС №6, №7
```

Каждая станция одновременно закреплена за одним менеджером и одним товароведом. Раздел «Структура контроля» отображает эту иерархию и позволяет редактировать контактный телефон каждого руководителя.

## 3. Типы чек-листов и распределение задач по ролям

Вместо единого общего списка задач продукт разделяет обязанности по ролям — так, как это устроено в реальной сети:

### 3.1 Чек-лист состояния АЗС (уровень смены, исполнитель — сотрудник, контролирует менеджер)
Выполняется каждой сменой (дневной и ночной) на каждой станции:
приём смены и пересчёт кассы; уборка территории; чистота торгового зала и туалета; исправность ТРК и показания счётчиков; контроль остатков топлива; приём топлива от бензовоза; инкассация выручки; кассовая дисциплина и чеки ККТ; противопожарное оборудование; заполнение журналов и передача отчёта.

### 3.2 Товароведческий чек-лист (уровень станции, исполнитель/ответственный — товаровед)
Выполняется по каждой станции, за которую отвечает товаровед:
наличие товарного ассортимента; отчёт по реализации товаров; ценники на товар; сроки годности продукции; выкладка товара; промо-материалы и рекламные стойки.

### 3.3 Задачи менеджера (уровень менеджера, по всем закреплённым станциям)
отчёт по реализации топлива за смену; отчёт по реализации сопутствующих товаров; контроль выполнения чек-листов состояния АЗС по закреплённым станциям; сверка выручки и инкассации по станциям.

### 3.4 Задачи начальника торгового отдела (уровень сети)
контроль заявок на пополнение ассортимента — по каждому из 3 товароведов; контроль соблюдения графика поставок поставщиками; проверка качества и комплектности поставок; контроль документооборота и оплаты поставщикам.

Все четыре шаблона чек-листов расширяемы: через форму «Добавить задачу в шаблон чек-листа» новая задача добавляется сразу во все текущие записи выбранного типа.

## 4. Жизненный цикл задачи

Ключевое требование: каждая задача проходит через фиксированный производственный цикл, а не является простым флажком «сделано / не сделано».

```
Постановка → Ответственный → Срок → Контроль → Подтверждение → Проверка → Закрытие
```

- **Постановка** — момент создания задачи (фиксируется автоматически).
- **Ответственный** — исполнитель, за которым закреплена задача (сотрудник смены, товаровед, менеджер или начальник торгового отдела).
- **Срок** — дедлайн выполнения (дата и время).
- **Контроль → Подтверждение → Проверка → Закрытие** — рабочие стадии, по которым задача продвигается кликом: сначала она «под контролем», затем исполнитель подтверждает выполнение, далее задачу проверяет контролирующее лицо, и только после этого она закрывается.

### 4.1 Правило автоматической просрочки

Если срок (дедлайн) наступил, а задача не находится в стадии «Закрытие», система автоматически отображает её статус как **«Просрочено»** — независимо от того, на какой из промежуточных стадий она находится. Статус просрочки снимается только в момент фактического закрытия задачи. Это правило считается вычисляемым и не требует ручной пометки.

### 4.2 Постановка задачи конкретному сотруднику

Отдельная форма «Поставить задачу сотруднику» позволяет создать произвольную задачу и назначить её любому конкретному человеку в сети — с выбором из списка (сотрудник смены / товаровед / менеджер / начальник торгового отдела), названием задачи и сроком выполнения (по умолчанию — через 24 часа). Новая задача сразу входит в стадию «Контроль» и попадает в общую статистику и просрочки на общих основаниях.

## 5. Функциональность дашборда

### 5.1 Сводные показатели (стат-плитки)
Станций в сети; % выполнения чек-листа состояния АЗС; % товароведческого контроля; % отчётности менеджеров; % по заявкам и поставщикам; общее количество просроченных задач по сети.

### 5.2 Структура контроля
Список руководителей (начальник торгового отдела, менеджеры, товароведы) с указанием закреплённых станций и редактируемым номером телефона.

### 5.3 Задачи менеджеров и начальника торгового отдела
Персональные карточки с чек-листами каждого руководителя, с учётом текущего фильтра по контролёру.

### 5.4 График/таблица выполнения по станциям
Для каждой из 7 станций — доля выполнения операционного и товароведческого чек-листов (две серии, раздельные цветные полосы), с переключением между графическим и табличным представлением. Станции отсортированы по убыванию суммарного процента выполнения.

### 5.5 Чек-листы по станциям
Развёрнутый список задач по каждой станции с фильтрами:
- **Контролёр** — показать только зону ответственности конкретного менеджера/товароведа/начальника;
- **Станция**;
- **Смена** (дневная/ночная);
- **Статус задачи** (все / в работе / закрыто / просрочено).

Каждая строка задачи показывает название, срок выполнения, текущий этап (с цветовой и текстовой индикацией), а также подсказку при наведении с полной информацией (постановка, ответственный, срок).

### 5.6 Управление сетью (формы)
- **Поставить задачу сотруднику** — персональное назначение задачи любому сотруднику с дедлайном.
- **Добавить АЗС** — с привязкой к менеджеру и товароведу.
- **Добавить смену** — с ФИО и телефоном сотрудника; срок задач чек-листа автоматически ставится на конец смены.
- **Добавить задачу в шаблон чек-листа** — расширение одного из четырёх типовых списков задач.

### 5.7 Связь с сотрудником через WhatsApp

На каждой строке задачи — кнопка **«💬 WhatsApp»**. При нажатии открывается чат WhatsApp с ответственным по этой задаче (менеджером, товароведом, сотрудником смены или начальником торгового отдела) с предзаполненным сообщением: название задачи, станция/зона, ответственный, срок и текущий статус. Отправка сообщения — действие самого пользователя внутри WhatsApp; инструмент только формирует ссылку `wa.me` с текстом и открывает её в новой вкладке.

Номера телефонов — редактируемые поля:
- для руководителей (начальник, менеджеры, товароведы) — в разделе «Структура контроля»;
- для сотрудников смены — прямо в карточке смены.

При отсутствии номера кнопка WhatsApp для задачи не отображается.

### 5.8 Прочее
Переключение светлой/тёмной темы; адаптивная вёрстка; вся палитра и статус-цвета подобраны по методике доступности (проверено валидатором палитры на контраст и цветовую слепоту).

## 6. Модель данных (концептуально)

| Сущность | Ключевые поля |
|---|---|
| Станция | id, название, адрес, закреплённый менеджер, закреплённый товаровед |
| Смена | станция, тип смены, сотрудник, телефон, список задач |
| Товароведческая проверка | станция, список задач |
| Отчёт менеджера | менеджер, список задач |
| Задачи начальника | список задач (сеть в целом) |
| Задача | название, этап (Контроль/Подтверждение/Проверка/Закрытие), срок, дата постановки, ответственный |
| Менеджер / Товаровед / Начальник | имя, телефон, список закреплённых станций (для менеджера и товароведа) |

## 7. Ограничения текущей реализации

- Инструмент реализован как самодостаточный HTML/CSS/JS-файл без серверной части: все данные хранятся в памяти браузера и **сбрасываются при перезагрузке страницы**. Постоянное хранение (база данных, синхронизация между пользователями) не реализовано.
- Номера телефонов в исходном состоянии — плейсхолдеры (условные казахстанские номера), не привязанные к реальным сотрудникам; их нужно донастроить перед реальным использованием.
- Кнопка WhatsApp открывает предзаполненный чат через `wa.me` — фактическая отправка сообщения остаётся действием пользователя; автоматическая рассылка без участия человека не предусмотрена и не входит в объём задачи.
- Нет авторизации/разграничения доступа: любой, у кого открыт файл, видит и может редактировать все данные сети.
- Нет уведомлений (push/email) о наступлении просрочки — просрочка видна только при открытии инструмента.

## 8. Возможные направления развития (не реализовано)

- Серверное хранение данных с многопользовательским доступом и историей изменений по каждой задаче.
- Авторизация по ролям (сотрудник видит только свои задачи, менеджер — свою зону и т. д.).
- Автоматические напоминания (WhatsApp/push) при приближении и наступлении просрочки, без ручного клика.
- Интеграция с реальной справочной системой сотрудников/АЗС вместо ручного ввода.
- Экспорт отчётов (за период, по станции, по сотруднику) в Excel/PDF.
- История стадий задачи (кто и когда перевёл её на следующий этап) для аудита.

## 9. История требований (как формировался объём задачи)

Документ восстанавливает последовательность запросов, на основе которых сложился текущий объём:

1. Запрос на ассистента по контролю выполнения задач сотрудниками АЗС — определены формат (интерактивный HTML-инструмент), стандартный набор задач АЗС и масштаб (сеть станций).
2. Уточнение оргструктуры сети: 7 АЗС, 2 менеджера, 1 начальник торгового отдела, 3 товароведа.
3. Уточнение зон ответственности по ролям: задачи менеджеров — отчётность по реализации; чек-лист состояния АЗС; для начальника торгового отдела — контроль работы с заявками и поставщиками; для товароведов — наличие товарного ассортимента и отчёт по реализации.
4. Требование к жизненному циклу задачи: Постановка → Ответственный → Срок → Контроль → Подтверждение → Проверка → Закрытие, с автоматическим переводом в статус «Просрочено» до фактического закрытия.
5. Требование добавить постановку задач каждому конкретному сотруднику.
6. Требование добавить возможность отправить задачу сотруднику через WhatsApp.
